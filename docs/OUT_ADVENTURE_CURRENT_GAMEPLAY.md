# 外出冒险当前玩法全量整理

本文档整理当前代码中真实存在、真实生效的外出冒险玩法。依据文件：

- `src/lib/outdoor-adventure/events.ts`
- `src/lib/outdoor-adventure/engine.ts`
- `src/features/outdoor-adventure/outdoor-adventure-screen.tsx`

说明：本文只描述当前实现。纪念品文案里写了但引擎没有读取的效果，会单独标为“仅文案预留/未实现”，不当作真实效果。

## 1. 初始状态

新建外出冒险调用 `createDefaultOutdoorAdventureState()`。

| 指标 | 初始值 | 真实作用 |
|---|---:|---|
| 天数 `day` | 1 | 决定区域推进、每日物资消耗、事件选择公式、小游戏轮次公式。 |
| 当天步数 `stepInDay` | 0 | 每次事件选择或小游戏结算成功推进后 +1；决定当天第几个行动槽、小游戏插入、事件选择公式。 |
| 体力 `stamina` | 5 | 每次事件选择 -1；每次小游戏结算或成功逃跑 -1；体力到 0 进入日终。 |
| 物资 `supply` | 20 | 核心生存资源；事件、小游戏、扎营会增减；`<= 0` 且无复活币则失败。 |
| 麻烦 `trouble` | 0 | 影响区域提前推进、事件选择 index、小游戏失败物资损失、小游戏逃跑概率。 |
| 复活币 `reviveCoins` | 0 | 物资耗尽时若 >0，则消耗 1 个并把物资设为 8。当前事件数据里没有实际产出复活币。 |
| 冒险的心 `heartCharges` | 1 | 每天 1 次小游戏失败原地重试机会；扎营到次日重置为 1。 |
| 当前区域 `regionId` | `doorstep-meadow` | 初始为门外草地；之后由天数和麻烦推进。 |
| 当前节点 `currentNode` | `event_lollipop_block` | 第一件事固定是“吃棒棒糖的小方块”。 |
| 初始纪念品 | 冒险的心、远行脚印 | 冒险的心实际生效；远行脚印当前只作为提示性纪念品展示。 |

## 2. 基础流程

一次冒险由“事件节点、小游戏节点、日终节点、总结节点”组成。

```text
进入冒险
→ 事件：左右二选一
→ 选择后立刻结算 outcome
→ 展示结果
→ 收起结果后进入 pendingNextNode
→ 下一个事件 / 小游戏 / 日终 / 失败 / 结算
```

每个普通事件默认消耗 1 体力，增加 1 当天步数。事件本身没有事件级权重，结果 outcome 才有权重。

一天默认有 5 点体力，所以最多推进约 5 次行动。普通推进中，事件和小游戏都会占用行动次数。

## 3. 体力、步数和日终

事件选择结算时：

- `stamina = max(0, stamina - (event.staminaCost ?? 1))`
- `stepInDay += 1`
- 记录事件 seen、choice、outcome 记忆
- 应用 outcome effects
- 若物资耗尽则处理失败/复活
- 若体力为 0，则进入日终
- 否则计算下一个节点

小游戏结算时：

- 成功、失败、成功逃跑都会 `stamina -1`、`stepInDay +1`
- 逃跑失败只扣 1 物资，不扣体力、不增加步数，也不离开小游戏节点
- 冒险的心拦截小游戏失败时，只扣 `heartCharges -1`，不扣体力、不扣物资、不推进步数

日终触发条件：

- 事件或小游戏结算后，若 `stamina <= 0`，进入 `currentNode = { kind: "day-end" }`
- 日终可“休息会继续冒险”或“结算冒险”

## 4. 自动小游戏插入

普通事件结算后，如果没有 outcome 强制触发小游戏，引擎用下面规则决定下一节点：

```ts
const nextSlot = state.stepInDay + 1
if (nextSlot === 2 || nextSlot === 4) {
  currentNode = mini-game
} else {
  currentNode = event
}
```

注意：事件结算时已经先 `stepInDay += 1`。因此实际表现是：

| 当前动作结算后的 `stepInDay` | `nextSlot` | 下一节点 |
|---:|---:|---|
| 1 | 2 | 自动小游戏 |
| 2 | 3 | 普通事件 |
| 3 | 4 | 自动小游戏 |
| 4 | 5 | 普通事件 |
| 5 | 6 | 日终，因为体力通常已经归 0 |

自动小游戏轮次由公式决定：

```ts
index = abs(day + stepInDay + trouble) % 3
OUTDOOR_MINI_GAME_ROUNDS = ["search", "stroop", "memory"]
```

对应小游戏：

| roundId | 标题 |
|---|---|
| `search` | 一路向上 |
| `stroop` | 一路向下 |
| `memory` | 一路向前 |

## 5. 区域推进

区域不是固定按剧情线推进，而是由天数和麻烦值动态决定。

```ts
if (day >= 6 || trouble >= 8) return "tower-alley"
if (day >= 3 || trouble >= 4) return "block-market"
return state.regionId ?? "doorstep-meadow"
```

| 条件 | 区域 | 说明 |
|---|---|---|
| 第 1-2 天，且麻烦 < 4 | 门外草地 `doorstep-meadow` | 初始区域。 |
| 第 3 天起，或麻烦 >= 4 | 方块集市 `block-market` | 麻烦高可提前进入。 |
| 第 6 天起，或麻烦 >= 8 | 高楼缝隙 `tower-alley` | 麻烦很高可提前进入。 |

### 麻烦值的真实影响

麻烦 `trouble` 当前真实影响四件事：

| 影响点 | 规则 |
|---|---|
| 区域提前推进 | `trouble >= 4` 进入方块集市；`trouble >= 8` 进入高楼缝隙。 |
| 下一事件选择 | 事件 index 使用 `day * 7 + stepInDay * 5 + trouble`。麻烦变化会改变下一个事件。 |
| 小游戏失败损失 | 基础损失 `5 + floor(trouble / 10)`，麻烦越高失败越痛。 |
| 小游戏逃跑概率 | `40 + 逃跑鞋数量 - trouble`，再夹在 5%-80%。麻烦越高越难逃跑。 |

麻烦当前不会直接导致失败，也不会直接改变事件 outcome 权重。

## 6. 事件选择公式

在当前区域内选择事件时，不是随机权重池，而是确定性取模：

```ts
index = abs(day * 7 + stepInDay * 5 + trouble) % regionEvents.length
```

特殊强制事件优先级高于公式：

| 区域 | 条件 | 强制事件 |
|---|---|---|
| 门外草地 | `piggyFedCount > 0 && piggyFedCount < 3 && (day + stepInDay) % 2 === 0` | `event_piggy_block` 路边的猪猪方块 |
| 高楼缝隙 | `trouble >= 6 && (day + stepInDay) % 5 === 0` | `event_mom_chase` 小方块老妈的远远一眼 |

## 7. 按天数和区域会发生什么

因为事件选择还受 `stepInDay` 和 `trouble` 影响，所以不存在“第 N 天固定发生某事件”的脚本表。真实规则如下：

| 天数/麻烦 | 可能区域 | 会发生什么 |
|---|---|---|
| 第 1 天开始 | 门外草地 | 第一事件固定是“吃棒棒糖的小方块”。之后按事件公式选择草地区域事件；第 1、3 次行动后通常插入小游戏。 |
| 第 1-2 天，麻烦 < 4 | 门外草地 | 继续从草地事件池取事件。若投喂过猪猪且次数未满 3，满足 `(day + stepInDay) % 2 === 0` 会强制再遇猪猪。 |
| 任意天，麻烦 >= 4 | 方块集市 | 即使还没到第 3 天，也会提前进入集市事件池。 |
| 第 3-5 天，麻烦 < 8 | 方块集市 | 正常进入集市事件池。 |
| 任意天，麻烦 >= 8 | 高楼缝隙 | 即使还没到第 6 天，也会提前进入缝隙事件池。 |
| 第 6 天起 | 高楼缝隙 | 正常进入高风险事件池。麻烦 >= 6 且 `(day + stepInDay) % 5 === 0` 时可能强制遇到小方块老妈。 |

## 8. 每日物资消耗

每日消耗只在日终选择“休息会继续冒险/扎营到次日”时发生，不会在自然跨天自动扣。

```ts
if (day <= 3 && trouble < 5) return 3
if (day <= 7) return 4
if (day <= 12) return 5 + floor(trouble / 8)
if (day <= 17) return 6 + floor(trouble / 6)
return 8 + floor(trouble / 5)
```

| 当前天数与麻烦 | 扎营消耗 |
|---|---:|
| day <= 3 且 trouble < 5 | 3 物资 |
| day <= 7 | 4 物资 |
| day <= 12 | `5 + floor(trouble / 8)` |
| day <= 17 | `6 + floor(trouble / 6)` |
| day >= 18 | `8 + floor(trouble / 5)` |

扎营到次日还会：

- `day += 1`
- `stepInDay = 0`
- `stamina = 5`
- `heartCharges = 1`
- 根据新天数和麻烦重新计算区域与下一事件

## 9. 失败、复活和结算

物资耗尽规则：

```ts
if (supply > 0) continue
if (reviveCoins > 0) {
  reviveCoins -= 1
  supply = 8
} else {
  status = "failed"
  currentNode = summary
}
```

当前事件数据没有产出 `reviveCoin` 的 outcome，所以复活币系统存在，但正常内容里基本不会触发。

结算规则：

- 只有玩家在日终选择结算，才调用 `finishOutdoorAdventure`
- 结算 summary 写入“第 X 天、剩余物资、纪念品件数”
- 当前没有“到达最终区域自动成功”或“完成目标自动胜利”
- 结束后页面接线会清理持久化外出冒险状态

## 12. 全事件明细

说明：

- 每个事件选择时统一 `体力 -1`、`stepInDay +1`，表格里不重复写。
- “权重”是该选项内部 outcome 的权重，不是全局概率；概率约等于 `该 outcome 权重 / 该选项所有 outcome 权重之和`。
- `memory` 是隐藏计数，会影响少量特殊复遇或记录，不一定有 UI 展示。

### 12.1 门外草地

#### 吃棒棒糖的小方块 `event_lollipop_block`

首次描述：路边坐着一个小方块，正在舔一根彩虹棒棒糖。它舔一下，看你一眼。

复遇描述：你又看见那个吃棒棒糖的小方块。它这次把糖举高了一点，像是在提前防守。

| 选项 | 提示 | outcome | 权重 | 结果文本 | 效果 |
|---|---|---|---:|---|---|
| 抢了就跑 | 可能拿到糖，也可能被记住。 | `stolen` | 55 | 你抢到了棒棒糖，跑得像一阵很心虚的风。 | 获得抢来的棒棒糖；麻烦 +2；结果提示“小方块妈妈记住了你”。 |
| 抢了就跑 | 同上 | `wrapper` | 25 | 棒棒糖没抢稳，只抢到一张破糖纸。小方块哭得很有穿透力。 | 获得破掉的糖纸；麻烦 +3；结果提示“小方块妈妈记住了你”。 |
| 抢了就跑 | 同上 | `mom` | 20 | 小方块老妈从路牌后面站了出来。她看起来不想讲道理。 | 麻烦 +4；强制触发小游戏“一路向下”；结果提示“小方块妈妈记住了你”。 |
| 礼貌地看向别处 | 收益小，但世界会记得你没下手。 | `small_supply` | 70 | 你假装没看到。小方块也假装没看到你在假装。 | 物资 +1；`memory.kindChoices +1`。 |
| 礼貌地看向别处 | 同上 | `half` | 30 | 小方块把半根棒棒糖递给你，表情像在颁奖。 | 获得半根棒棒糖；`memory.kindChoices +1`。 |

后续影响：抢来的棒棒糖会让小游戏失败物资损失 -1；半根棒棒糖会让小游戏成功额外 +1 物资。

#### 路边的猪猪方块 `event_piggy_block`

首次描述：一只猪猪方块堵在路中间，盯着你的口袋。它没有说话，但肚子替它说了。

复遇描述：路边又出现猪猪方块。这次饭碗已经摆好，旁边还挤着一个小一点的饭碗。

特殊复遇：在草地区域，`piggyFedCount > 0 && piggyFedCount < 3 && (day + stepInDay) % 2 === 0` 时会强制遇到。

| 选项 | 提示 | outcome | 权重 | 结果文本 | 效果 |
|---|---|---|---:|---|---|
| 投喂一点 | 会记录投喂次数，第三次可能很好。 | `fed` | 100 | 猪猪方块认真吃完，还把空碗推回给你。 | 物资 -3；麻烦 -1；`memory.piggyFedCount +1`；结果提示“猪猪方块记住了这次投喂”。 |
| 投喂一点 | 同上 | `fed_bonus` | 1 | 猪猪方块吃完后偷偷塞给你一张饭票。 | 物资 -3；获得猪猪饭票；`memory.piggyFedCount +1`；结果提示“猪猪方块记住了这次投喂”。 |
| 告诉它健康饮食很重要 | 省物资，但猪猪不一定爱听。 | `walk_away` | 80 | 猪猪方块慢慢让开，看起来并没有被说服。 | 物资 +1。 |
| 告诉它健康饮食很重要 | 同上 | `mud` | 20 | 猪猪方块在地上滚了一圈，把泥巴印甩到了你身上。 | 获得泥巴印；麻烦 +1。 |

后续影响：`piggyFedCount >= 3` 且还没有猪猪储蓄罐时，会自动获得猪猪储蓄罐。当前 `event_piggy_block` 有 resolvedDescription，但没有 `resolvedChoiceIds`，所以 resolved 文案实际不会触发。

## 13. 记忆和复遇

每次事件选择后自动写入：

```ts
event:${eventId}:seen += 1
event:${eventId}:choice:${optionId} += 1
event:${eventId}:outcome:${outcomeId} += 1
```

部分 outcome 额外写入业务记忆：

| memory key | 来源 | 当前真实作用 |
|---|---|---|
| `kindChoices` | 礼貌、帮助、善意类 outcome | 当前主要记录，暂未参与事件权重或结算。 |
| `piggyFedCount` | 猪猪投喂 | 1-2 次时可强制复遇猪猪；达到 3 次自动获得猪猪储蓄罐。 |
| `rumorRead` | 传闻纸条认真读完 | 当前只记录，暂无后续读取。 |
| `lecturedByMom` | 老妈教育 outcome | 当前只记录，暂无后续读取。 |
| `escapeTechnique` | 小游戏逃跑成功 | 当前只记录，同时逃跑成功会获得逃跑鞋。 |

复遇展示规则：

1. 如果事件有 `resolvedDescription`，且玩家选过 `resolvedChoiceIds` 中任一选项，显示 resolved 文案。
2. 否则，如果 `event:${eventId}:seen > 0` 且事件有 `repeatDescription`，显示 repeat 文案。
3. 否则显示首次文案。

重要限制：

- `seen` 是选择后增加，不是看到事件时增加。
- repeat/resolved 只影响描述，不改变选项、权重和 outcome。
- 当前没有通用 flags 系统。

## 17. 当前设计限制

- 没有事件级随机权重；事件选择是区域内确定性取模。
- 没有通用条件系统；大部分特殊逻辑是硬编码。
- 没有通用 flags；`memory` 同时承载系统计数和剧情计数。
- 很多纪念品文案说会影响权重、价格、结算、消耗，但当前没有实现。
- 麻烦值不会直接失败，只会影响区域、事件 index、小游戏损失和逃跑概率。
- 体力不影响事件成功率或小游戏难度，只控制当天行动次数。
- 日终结算没有永久收藏转移、纪念品带回概率、债务扣奖等系统。
- `event_piggy_block` 有解决文案但没有解决条件，所以不会进入 resolved 展示。
